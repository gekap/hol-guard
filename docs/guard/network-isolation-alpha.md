# Network isolation alpha

HOL Guard 3.0 network isolation is being integrated through the canonical Guard policy, approval, daemon, evidence, provider-recovery, and native-artifact authorities.

Capabilities remain unavailable unless the current host has an installed, identity-verified provider, a fresh live probe, an active matching policy generation, and behavioral evidence. Static contracts, reference plans, object presence, or provider self-report do not establish protection.

The first enforcing target is Linux cgroup-v2 TCP destination control through a packaged privileged helper. Bounded Seatbelt and Bubblewrap offline containment remains limited to actions Guard launches from a verified bounded snapshot. macOS and Windows selective egress remain unavailable until separately approved native providers and lifecycle evidence exist.

This work does not authorize release, deployment, managed activation, or general availability.
